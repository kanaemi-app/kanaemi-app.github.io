自分の OS を選んでください。入れたあと、入力ソース（キーボード）に Kanaemi を足すと使えます。

<Tabs syncKey="os">
<TabItem label="macOS">

Apple シリコン（M1 以降）の Mac で使えます。Intel の Mac 向けはありません（Apple メニューの「この Mac について」の「チップ」に「Apple M1」などと出ていれば Apple シリコンです）。

<InstallerDownloads os="macos" />

### macOS に入れる

<Steps>

1. `Kanaemi-<版>.pkg` を開き、インストーラーに従って入れる。はじめて開くときは警告が出て開けないので、下の「開けないとき」の手順で開く。

2. 「システム設定 › キーボード › 入力ソース」の「編集…」を開き、「＋」から「日本語」の下にある Kanaemi を足す。

   一覧に出てこないときは、[困ったとき](/docs/troubleshooting/#macos-で入力ソースの一覧に出ない) を見てください。

3. メニューバーの入力メニューで Kanaemi を選ぶ。

</Steps>

[Homebrew](https://brew.sh/) なら、1 の代わりに次を流します。この入れ方では警告が出ません。

```sh
brew install --cask kanaemi-app/tap/kanaemi
```

インストーラーで入れた Kanaemi がすでにあると、Homebrew は止まります。そのときは `--force` を付けます（`brew install --cask --force kanaemi-app/tap/kanaemi`）。置き換わるのはアプリだけです。

[Nix](https://nixos.org/) なら、1 の代わりに次を流します。`<版>` には [リリース](/docs/releases/) の版を入れます。組み立て済みのものを [kanaemi.cachix.org](https://kanaemi.cachix.org) から取ってくるので、手元でビルドしません。このキャッシュを使ってよいか Nix が尋ねたら、許してください。

```sh
nix build github:kanaemi-app/kanaemi/v<版>
rm -rf ~/Library/Input\ Methods/Kanaemi.app
cp -R result/Applications/Kanaemi.app ~/Library/Input\ Methods/
chmod -R u+w ~/Library/Input\ Methods/Kanaemi.app
```

新しくするときは、新しい版で同じものを流します。Nix で組み立てた Kanaemi はリリースの証明書で署名していないので、新しくするたびに [許可](#macos-の許可) をし直します。

<details>
<summary>開けないとき（「Apple は、マルウェアが含まれていないことを検証できませんでした」）</summary>

インストーラーが Apple の公証を受けていないため、macOS ははじめて開くときに止めます。

<Steps>

1. 警告の画面で「完了」を押して閉じる。

2. 「システム設定 › プライバシーとセキュリティ」の下のほうの「セキュリティ」で、`Kanaemi-<版>.pkg` についての「このまま開く」を押す。

3. もう一度出る確認で「このまま開く」を押し、パスワードか Touch ID で許可する。

</Steps>

「このまま開く」は、警告が出てからしばらくしか出ません。見当たらなければ、もう一度 `.pkg` を開いて警告を出してから、システム設定を開き直します。

ターミナルなら、ダウンロードしたファイルの印を外してから開くこともできます。

```sh
xattr -d com.apple.quarantine ~/Downloads/Kanaemi-*.pkg
```

</details>

### macOS の許可

次の機能を使うときだけ、「システム設定 › プライバシーとセキュリティ」で Kanaemi を許可します。

| 許可 | 要る機能 | 許可がないとき |
| --- | --- | --- |
| アクセシビリティ | [ふだんの置き換え](/docs/settings/keys/#ふだん)・[確定した候補を選び直す](/docs/usage/candidates/#確定した候補を選び直す) | 押したキーをそのままアプリに渡す |
| 入力監視 | [押さえたまま](/docs/settings/keys/#押さえたまま)（SandS など） | 押さえたままに割り当てたキーは、いつも単独で押したものとして働く |

- 許可がないあいだは、入力メニューに許可の設定を開く項目が出ます。[設定アプリ](/docs/settings/app/#キーバインド) のキーバインドからも開けます。
- 許可の一覧に Kanaemi がなければ、`~/Library/Input Methods/Kanaemi.app` を一覧にドラッグしてオンにします。設定アプリから許可の設定を開くと、この場所も Finder で開きます。
- どの版も同じ証明書で署名しているので、新しい版を入れても、たいてい許可は残ります。新しくしたあとに働かなくなったら、許可し直してください。

### macOS から消す

入力ソースから Kanaemi を外し、`~/Library/Input Methods/Kanaemi.app` を消します。

```sh
rm -rf ~/Library/Input\ Methods/Kanaemi.app
```

Homebrew で入れたときは、`brew uninstall --cask kanaemi` で消します。

### Windows でどれを選ぶか

ほとんどのパソコンは「Intel・AMD の CPU」です。Snapdragon などの Arm の CPU のパソコンだけ、「Arm の CPU」を選びます。

分からないときは、「設定 › システム › バージョン情報」の「システムの種類」を見ます。「x64 ベース プロセッサ」なら Intel・AMD、「ARM ベース プロセッサ」なら Arm です。

### Windows に入れる

<Steps>

1. `.msi` を開き、インストーラーに従って入れる。警告が出たら、下の「警告が出たとき」を見る。

2. 「設定 › 時刻と言語 › 言語と地域」で日本語の「言語のオプション」を開き、「キーボードの追加」から Kanaemi を足す。

3. タスクバーの入力インジケーター（<kbd>Win</kbd>＋<kbd>Space</kbd>）で Kanaemi を選ぶ。

</Steps>

設定アプリは、スタートメニューの「かなえみ設定」から開けます。

<details>
<summary>警告が出たとき</summary>

インストーラーは Microsoft が確かめられる署名を受けていないため、Windows やブラウザーが警告を出すことがあります。

- 「Windows によって PC が保護されました」：「詳細情報」を押し、出てきた「実行」を押す。
- 「ユーザー アカウント制御」で発行元が「不明」：「はい」を押す。
- ブラウザー（Microsoft Edge など）がダウンロードを止めた：ダウンロードの一覧のそのファイルのメニューから「保存」や「保持する」を選ぶ。

</details>

### Windows から消す

「設定 › アプリ」から Kanaemi をアンインストールします。

### Linux でどれを選ぶか

パッケージは、入力の仕組みと CPU で分かれています。

- 入力の仕組み：GNOME（Ubuntu や Fedora の標準）など IBus なら「IBus 用」、KDE Plasma など Fcitx5 なら「Fcitx5 用」。分からないときは `echo $XMODIFIERS` を流し、`@im=ibus` なら IBus、`@im=fcitx` なら Fcitx5 です。
- CPU：`uname -m` が `x86_64` なら「Intel・AMD の CPU」、`aarch64` なら「Arm の CPU」。

設定アプリは、どちらのパッケージにも入っています。両方を入れても、ぶつかりません。

### Linux に入れる

<Steps>

1. パッケージを入れる。

   ```sh
   # IBus 用：Debian・Ubuntu
   sudo apt install ./ibus-kanaemi_*.deb
   # IBus 用：Fedora など
   sudo dnf install ./ibus-kanaemi-*.rpm

   # Fcitx5 用：Debian・Ubuntu
   sudo apt install ./fcitx5-kanaemi_*.deb
   # Fcitx5 用：Fedora など
   sudo dnf install ./fcitx5-kanaemi-*.rpm
   ```

2. 入力ソースに Kanaemi を足す。

   - IBus 用：GNOME なら、「設定 › キーボード › 入力ソース」の「＋」から「日本語」の下にある Kanaemi を足す。ほかのデスクトップでは、IBus の設定（`ibus-setup`）から足す。
   - Fcitx5 用：Fcitx5 の設定（`fcitx5-configtool`）の「入力メソッド」で、Kanaemi を右の一覧に足す。

3. 入力ソースを Kanaemi に切り替える。

</Steps>

### NixOS に入れる

NixOS では、1 のパッケージの代わりに flake を使います。flake の inputs に `kanaemi.url = "github:kanaemi-app/kanaemi/v<版>";` を足し（`<版>` は [リリース](/docs/releases/) の版）、使う入力の仕組みにパッケージを渡します。IBus 用と Fcitx5 用は同じパッケージです。組み立て済みのものを [kanaemi.cachix.org](https://kanaemi.cachix.org) から取ってくるよう、キャッシュも足します。

```nix
{ inputs, pkgs, ... }:
let
  kanaemi = inputs.kanaemi.packages.${pkgs.stdenv.hostPlatform.system}.kanaemi;
in
{
  i18n.inputMethod.ibus.engines = [ kanaemi ]; # IBus のとき
  i18n.inputMethod.fcitx5.addons = [ kanaemi ]; # Fcitx5 のとき
  nix.settings = {
    extra-substituters = [ "https://kanaemi.cachix.org" ];
    extra-trusted-public-keys = [ "kanaemi.cachix.org-1:TIkDbHQ6HmPzHQBXdOVhLSTff2LiCWJOJhKdIUWC238=" ];
  };
}
```

設定を反映したら、2 から続けます。新しくするときは、`kanaemi.url` の版を書き換えてから、flake の inputs を更新します（`nix flake update kanaemi`）。

### Linux で気をつけること

- X11 の GTK3 のアプリでは、GTK3 の入力モジュール（IBus なら `ibus-gtk3`、Fcitx5 なら `fcitx5-frontend-gtk3`）がないと、キーが Kanaemi に届きません。
- Fcitx5 は、既定では左の <kbd>Shift</kbd> の単独押しを自分で取るので、そのままでは左の <kbd>Shift</kbd> で ABC モードになりません。変え方は [困ったとき](/docs/troubleshooting/#linux-の-fcitx5-で左の-shift-で-abc-モードにならない) にあります。

### Linux から消す

入れたときと同じパッケージマネージャーで消します（`sudo apt remove ibus-kanaemi` や `sudo apt remove fcitx5-kanaemi` など）。NixOS では、設定からパッケージを外して反映します。

## 次に

Kanaemi は辞書がなくても動きますが、変換しても候補が出ません。[辞書を入れる](/docs/dictionaries/) に進んでください。

## 消しても残るもの

Kanaemi を消しても、[設定のフォルダ](/docs/settings/folder/) は残ります。設定や登録した語ごと消すときは、このフォルダも消してください。
