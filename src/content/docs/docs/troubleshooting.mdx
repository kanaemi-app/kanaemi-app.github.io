まずは [ログ](/docs/settings/folder/#ログ) を見てください。設定や辞書の読めなかったところは、ログに残ります。

## 変換しても候補が出ない

辞書が入っていないかもしれません。[設定アプリで公式辞書を入れて](/docs/dictionaries/#設定アプリで入れる) ください。入れたあとは、入力欄をクリックし直すと読み込まれます。

設定ファイルに `dictionaries` を書いているときは、その一覧にない辞書は使われません。

## 設定を変えたのに反映されない

- 入力欄をクリックし直してください。Kanaemi は、入力欄にフォーカスが入るときに設定を読み直します。
- 行頭の `#` を外したか確かめてください。ひな形の設定は、コメントのままでは有効になりません。
- 読めない設定は飛ばして既定値を使います。ログか [設定アプリ](/docs/settings/app/) で、読めなかった設定とそのわけを見られます。

## Shift の単独押しでモードが変わらない

<kbd>Shift</kbd> を押してから離すまでが 300 ミリ秒を超えると、単独押しになりません。ゆっくり押す癖があるときは、`[keys] tap_timeout_ms` を長くしてください。

Linux の Fcitx5 では、下の [左の Shift で ABC モードにならない](#linux-の-fcitx5-で左の-shift-で-abc-モードにならない) も見てください。

## macOS で入力ソースの一覧に出ない

入れた直後は、システム設定の入力ソースの一覧に出ないことがあります。

1. システム設定を終了する。
2. ターミナルで、入力ソースの一覧のキャッシュを消す。

   ```sh
   rm "$(getconf DARWIN_USER_CACHE_DIR)"/com.apple.IntlDataCache.le*
   ```

3. システム設定を開き直す。

管理者の権限もログアウトも要りません。

## macOS で SandS（押さえたまま）が効かない

macOS の「入力監視」で Kanaemi を許可していないと、押さえたままに割り当てたキーは、いつも単独で押したものとして働きます。許可がないあいだは、メニューバーの入力メニューに「入力監視の設定を開く…」が出ます。[macOS の許可](/docs/install/#macos-の許可) を見てください。

## macOS で置き換えや Shift＋Backspace・Ctrl＋; が効かない

キーを送る機能（[ふだんの置き換え](/docs/settings/keys/#ふだん)、[確定した候補を選び直す](/docs/usage/candidates/#確定した候補を選び直す)、[打ったかなを読みに戻す](/docs/usage/convert/#打ったかなを読みに戻す)）には、「アクセシビリティ」の許可が要ります。[macOS の許可](/docs/install/#macos-の許可) を見てください。

## macOS で Ctrl＋H などが Backspace に置き換わらない

<Since feature="os-remaps" />

macOS では、<kbd>Ctrl</kbd>＋<kbd>H</kbd>・<kbd>Ctrl</kbd>＋<kbd>A</kbd> などの Emacs 風のキーを置き換えません。macOS の文字の入力欄が、もともと同じように扱うからです。置き換えたいときは、`[keys.application.macos]` に書いてください（[OS ごとの置き換え](/docs/settings/keys/#os-ごとの置き換え)）。

## 置き換えたくないアプリがある

<Since feature="send-except" />

ターミナルや Emacs のように、<kbd>Ctrl</kbd>＋<kbd>H</kbd> などを自分で扱うアプリでは、`[keys] send_except` にアプリを書くと、置き換えずにそのまま渡します（[キーを置き換えないアプリ](/docs/settings/keys/#キーを置き換えないアプリ)）。

## macOS で日本語を打てなくなった

ほかのアプリが Secure Input（パスワードを打つときなどに、キーの入力をほかから読めなくする仕組み）を有効にしたままだと、どの入力方式でも日本語を打てません。そのあいだ、Kanaemi はメニューバーの入力メニューとログに、Secure Input を有効にしているアプリの名前を出します。そのアプリのパスワードの入力欄を閉じるか、アプリを終了してください。

## macOS でメニューバーのアイコンが古いまま

入力ソースから Kanaemi を一度外し、足し直すと直ります。

## Linux（X11 の GTK3 アプリ）でキーが届かない

IBus 版では、IBus の入力モジュール `ibus-gtk3` が要ります。Fcitx5 版では、Fcitx5 の GTK の入力モジュール（Debian では `fcitx5-frontend-gtk3`・`fcitx5-frontend-gtk4`）が要ります。パッケージマネージャーで入れてください。

## Linux の Fcitx5 で左の Shift で ABC モードにならない

<Since feature="fcitx5" />

Fcitx5 の既定の設定では、左の <kbd>Shift</kbd> の単独押しを Fcitx5 が「入力メソッドを一時的に切り替える」キーとして取るため、Kanaemi に届きません。Fcitx5 の設定でそのキー（`~/.config/fcitx5/config` の `[Hotkey/AltTriggerKeys]`）を空にするか、ABC モードにする別のキー（<kbd>英数</kbd>・<kbd>無変換</kbd> など）を使ってください。

## Linux の Fcitx5 で置き換えが効かない

<Since feature="fcitx5" />

Sway のような、Wayland の入力メソッドのプロトコルの第 2 版を使うデスクトップの Fcitx5 では、送るキーに押している修飾キーが付いてしまうため、[ふだんの置き換え](/docs/settings/keys/#ふだん) をしません。押したキーは、そのままアプリに渡ります。[確定した候補を選び直す](/docs/usage/candidates/#確定した候補を選び直す) と [打ったかなを読みに戻す](/docs/usage/convert/#打ったかなを読みに戻す) は、<kbd>Backspace</kbd> を送らずに入力欄の文字を消すので、そのまま使えます。

## Linux で入力欄を移ると打ちかけが消える

IBus の作りのため、IBus 版ではフォーカスが外れたときに未確定文字列を確定せずに捨てます。Wayland の Fcitx5 版でも、フォーカスが外れたあとの確定は入力欄に届かず、打ちかけが消えることがあります。ほかの OS では確定します。

## 不具合を見つけたら

[GitHub の Issues](https://github.com/kanaemi-app/kanaemi/issues) に、OS とその版、何をしたらどうなったか、ログを添えて知らせてください。ログの打った文字は伏せてあるので（[ログ](/docs/settings/folder/#ログ)）、そのまま付けられます。
